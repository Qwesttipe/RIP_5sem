## Структура API

### Домен «Услуги»
- `GET /api/services` — список услуг (без авторизации — только чтение).  
- `GET /api/services/{id}` — подробная информация об услуге.  
- `POST /api/services` — создание услуги (только модератор).  
- `PUT /api/services/{id}` — изменение услуги (только модератор).  
- `DELETE /api/services/{id}` — удаление услуги (только модератор).  
- `POST /api/services/{id}/image` — загрузка или замена изображения услуги (только модератор).  

### Домен «Заявки»
- `GET /api/cart` — корзина (только для авторизованного пользователя).  
- `GET /api/orders` — список заявок (фильтрация по роли: создатель/модератор).  
- `GET /api/orders/{id}` — подробности заявки с услугами.  
- `PUT /api/orders/{id}` — изменение полей заявки (создатель).  
- `PUT /api/orders/{id}/form` — формирование заявки (создатель).  
- `PUT /api/orders/{id}/complete` — завершение или отклонение заявки (модератор).  
- `DELETE /api/orders/{id}` — логическое удаление заявки.  

### Домен «М-М» (услуги в заявке)
- `PUT /api/orders/{orderId}/items/{itemId}` — изменение количества/порядка.  
- `DELETE /api/orders/{orderId}/items/{itemId}` — удаление услуги из заявки.  

### Домен «Пользователь»
- `POST /api/users/register` — регистрация.  
- `POST /api/users/login` — аутентификация (куки / JWT).  
- `POST /api/users/logout` — деавторизация и удаление сессии.  
- `GET /api/users/me` — данные текущего пользователя.  
- `PUT /api/users/me` — редактирование данных пользователя.

## Требования к реализации
- Хранение сессий и куки через Redis.  
- Авторизация через JWT для защищённых эндпоинтов.  
- Проверка ролей и прав доступа (permissions) для модератора.  
- Автозаполнение пользователя при создании новой заявки.  
- Завершение заявки модератором приводит к расчёту расхода материалов и обновлению даты завершения.  
- Методы без авторизации должны возвращать только чтение (GET).  
- Swagger должен описывать все эндпоинты с указанием требований к авторизации.

## Структура моделей
1. **Пользователь (User)**  
   - username, password, is_moderator, id.  

2. **Заявки (Orders)**  
   - id, status, created_at, formed_at, completed_at, creator_id, moderator_id.  

3. **Материалы / Услуги (Material / Service)**  
   - id, title, description, consumption, count, image_url.  

4. **Заявка–Материал (м-м)**  
   - order_id, material_id, wall_length, material_consumption, mortar_consumption.

## Статусы заявок
- Черновик  
- Удалён  
- Сформирован  
- Завершён  
- Отклонён

## Порядок демонстрации
1. Выполнить аутентификацию через Swagger или Postman (получение куки/JWT).  
2. GET списка заявок:  
   - Неавторизованный → 401/403  
   - Создатель → только свои заявки  
   - Модератор → все заявки  
3. PUT завершения заявки:  
   - Создатель → 403  
   - Модератор → успешное завершение, обновление полей.  
4. Проверка расчёта расхода материалов после завершения заявки.  
5. GET списка услуг и заявок после изменений.  
6. Проверка сессий через Redis (cmd или GUI).  
7. Swagger: показать описание всех методов и возможность тестирования.
